## 1. 面试官从简历出发，到底会从哪些角度问？

这一节是**方法论**：把网上（JavaGuide 面试通关计划、面试官视角文章、微服务面试总结、Rust 作品集讨论等）反复出现的提问角度做了一次收敛，归纳成 8 大类、40 个角度。每个项目文档里的题目都会标注它属于哪个角度（`[A3]`、`[D2]` 这种编号）。

### 1.2 四层深度：同一个问题，答到什么程度算过关

| 层级 | 自测方式 | 举例（多租户） |
| --- | --- | --- |
| L1 能回答 | 30～60 秒说出结论和关键词 | 「我们用的是共享库共享表 + tenant_id 逻辑隔离」 |
| L2 能追问 | 解释原理、适用条件、失败方式、替代方案 | 「为什么不用独立库？因为租户数量多、成本高；代价是每张业务表都要带 tenant_id，所有 SQL 都要拼租户条件，漏一处就串租户」 |
| L3 能落到项目 | 说明项目里是否用了、为什么这么选、遇到什么限制、怎么验证 | 「落地在租户拦截器 + MyBatis 处理链，另外单独开了一个跨租户查询的旁路，只有平台管理端能用」 |
| L4 能扛反例 | 面试官给一个反例场景，你能说出边界和补救 | 「如果租户要单独导出数据做审计，逻辑隔离做不到物理分离，我们的补法是……」（说不出来就承认，比编好） |

> **红线**：任何一层都**不要编造生产数据**。没有生产指标就用测试环境数据，并主动说明机器配置、数据量、并发模型、测试时长。编一个「QPS 8000」被追问一句就崩，代价远大于数字小一点。

### 1.3 每个项目建议准备的两个版本

- **30 秒版**：业务 + 我的职责 + 一个最亮的点。（面试官说「先简单介绍一下」时用）
- **3 分钟版**：业务背景 → 架构一张图 → 核心链路 → 技术选型理由 → 一个难点 → 一个可继续追问的钩子。

不要在 3 分钟里把所有技术都点一遍——**每个技术名词都是一次「请展开」的邀请**，点多了就是给自己挖坑。每个项目文档的 §0 都写好了这两版的口播稿。

## 2. 通用高频问题（四个项目都会被问到的）

这些不依赖具体项目，但会从任何项目里被引出来。每份项目文档只写该项目特有的部分，共性部分看这里。

### 2.1 开场三连

1. 「挑一个你最有收获 / 最有挑战的项目讲讲。」→ 用该项目 §0 的 3 分钟版，结尾主动抛钩子。
2. 「这个项目里你具体负责什么？」→ 说清楚**边界**。开源框架给的、队友写的，明确说不是自己写的（A7）。
3. 「遇到的最大困难是什么，怎么解决的？」→ 必须是「现象 → 定位 → 修复 → 验证」四段完整的故事，不能只说结论（A5）。

### 2.2 设计模式：面试官最爱问的「送分题/送命题」

简历里写了「23 种设计模式、5 大设计原则」，所以**一定会被问「你说说项目里用到了哪些设计模式」**。这条答不好，前面所有内容都会被怀疑。

答题结构（推荐固定成肌肉记忆）：

> **模式名 → 落在哪个文件/类 → 解决什么问题 → 不用它会怎样 → 它的代价**

常见踩坑：

| 错误答法 | 为什么错 | 正确方向 |
| --- | --- | --- |
| 罗列 23 个模式名 | 面试官立刻知道你只是背过 | 只讲 3～5 个，每个都能指到具体代码 |
| 「框架用了，所以我也算用了」 | 分不清自己和框架 | 区分「框架内部」和「我在框架之上写的扩展」 |
| 把「if-else」说成策略模式 | 一眼假 | 策略模式的判据是**有接口 + 有多个实现类 + 调用方不感知具体实现** |
| 讲了模式但说不出代价 | 缺少工程判断 | 每个模式都要能说「它增加了 X 层间接，换来 Y」 |

四个项目已确认的「模式富矿」位置（详细拆解见各项目文档 §3）：

- **WestChina-Cloud**：模板方法（若依 `BaseController`/`BaseServiceImpl`）、策略（多 AI 推理方案）、工厂 + 单例（Spring 容器 / `SpringUtils`）、责任链（网关过滤器链）、观察者（MQ 监听）、门面（各模块 Service 对 Controller 的收敛）
- **encoding_practice**：策略 / 表驱动（字段编解码）、建造者（组包）、迭代器（位流读取）、模板方法（协议处理主流程）、适配器（UDP 仿真层）
- **风声**：状态机（对局 FSM）、命令 / 意图队列（`intentQueue`）、责任链 + 中断栈（`interruptStack`）、观察者（`eventStream`）、备忘录（`snapshot`）、中介者（`flowHub`）、注册表（`chainRegistry`）
- **rust-compile-web**：外观（后端 API 对 rustc 的封装）、策略（各编译阶段输出聚合）、适配器 / DTO（AST 解析成前端树）、观察者（Pinia store 驱动视图）

### 2.3 CAP / BASE：怎么答才不像背书

面试官问 CAP，99% 是因为简历上写了「分布式理论（BASE, CAP）」。标准送命答法是背三个字母。正确姿势是**用一个项目里的真实决策去套**：

| 理论 | 一句话本质 | 项目里的套法（举例） |
| --- | --- | --- |
| CAP | 分区容忍必须保，只能在一致性和可用性之间取舍 | 「多租户 SaaS 我们偏 AP：网关和认证服务多实例，某个实例挂了仍可登录（可用性优先）；代价是配置缓存有秒级不一致，靠消息广播收敛」 |
| BASE | 基本可用 + 软状态 + 最终一致，是 AP 的工程化延伸 | 「AI 病灶识别走 MQ 异步：接口立刻返回任务 ID（基本可用），任务表状态是软状态（处理中），识别完成后回写结果（最终一致）」 |
| 为什么不能三者兼得 | 网络分区时，写请求要么拒绝（保 C 丢 A）要么接受（保 A 丢 C） | 「用一个反例讲：跨机房双写，网络断了要么拒绝写要么接受冲突」 |

**关键**：一定要能说出「我们项目**没有**用到强一致的地方是什么，以及为什么不用」。承认没做过的部分，比硬套可信得多。

### 2.4 场景设计题（Boss 级）

面试官会给一个你项目里没有的场景（秒杀、大文件上传、消息防刷、跨机房、多租户设计）。答题顺序建议固定：

1. 先问清需求与约束（用户量、QPS、延迟、一致性、可用性）——**不问就答是最大的扣分项**
2. 给出核心业务链路、数据模型、接口
3. 给一个能跑起来的最简方案
4. 按瓶颈加缓存/异步/分片/限流/降级
5. 说明失败场景、一致性、监控与验证方式

把它和你项目里的真实模块**接回去**：「这个场景我在 WestChina 里遇到过类似的，我们当时是……」

### 2.5 反问环节

不要问「加班多吗」。可以问：

- 这个岗位现在最急的技术问题是什么？
- 团队的技术栈迭代节奏是怎样的？
- 这个项目的代码 review 和测试流程是怎样的？

## 4. 全局红线（四份文档共同遵守）

1. **区分「我写的」和「框架/队友写的」**。若依（RuoYi）脚手架自带的东西，说成「基于若依二次开发」而不是「我从零设计」。
2. **数字必须有来源**。测试环境数据要标注环境；没测过的不要说。
3. **不会就说不会**，并给出「如果现在做我会怎么做」。编答案的存活率低于承认不知道。
4. **每个技术名词都要能顶住一句「展开讲讲」**。写进简历的每个词，先自问三层：是什么、为什么用它、项目里哪里用了。
5. **难点故事必须能画出时间线**。没有细节的「困难」听起来就是假的。

- [JavaGuide · 从面试官和候选者的角度谈如何准备技术初试](https://javaguide.cn/high-quality-technical-articles/interview/technical-preliminary-preparation.html) — 面试官通常让候选人挑一个最有收获/最有挑战的项目，再从项目背景出发发问。
- [程序员如何写简历（CppGuide）](https://github.com/balloonwj/CppGuide/blob/master/articles/%E7%A8%8B%E5%BA%8F%E5%91%98%E7%9A%84%E7%AE%80%E5%8E%86/%E7%A8%8B%E5%BA%8F%E5%91%98%E5%A6%82%E4%BD%95%E5%86%99%E7%AE%80%E5%8E%86.md) — 「该项目使用了 RPC 框架和分布式？设计模式、策略模式、单例模式、工厂模式」：面试官会直接从简历里的技术名词切入。
- [嵌入式软件工程师面试 · 如何在面试中介绍自己的项目经验](https://github.com/ZhongYi-LinuxDriverDev/EmbeddedSoftwareEngineerInterview/blob/main/%E7%AC%94%E8%AF%95%E9%9D%A2%E8%AF%95%E6%8A%80%E5%B7%A7/%E5%A6%82%E4%BD%95%E5%9C%A8%E9%9D%A2%E8%AF%95%E4%B8%AD%E4%BB%8B%E7%BB%8D%E8%87%AA%E5%B7%B1%E7%9A%84%E9%A1%B9%E7%9B%AE%E7%BB%8F%E9%AA%8C.md) — 项目介绍的常见问法与准备方式。
- [面渣逆袭：微服务三十三问](https://blog.csdn.net/github_38592071/article/details/140089338) — 微服务 / SaaS 多租户方向的追问清单。
- [若依多租户功能解决方案解析](https://blog.csdn.net/weixin_53883156/article/details/147188903) — 基于若依实现多租户的常见思路，用于对照 WestChina-Cloud 的实现。
- [r/rust · 你作品集里哪个 Rust 项目让你被聘为 Rust 开发者](https://www.reddit.com/r/rust/comments/u74d7x/what_was_the_rust_project_in_your_portfolio_that/?tl=zh-hans) — Rust 岗位更看重「能否讲清设计取舍」，而非年限。
- [知乎 · Java 后端面试面 10 家拿下 6 个 offer 的实用打法](https://zhuanlan.zhihu.com/p/2046272364917298649) — 架构设计大题的回答顺序：数据一致性 → 服务容错 → 水平扩容。
- [工程师面试指北（蛮荆）](https://dbwu.tech/posts/other/interview/) — 面试前复盘项目、主动找设计缺陷。
