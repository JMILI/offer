### 1.1 框架架构设计（职责第 1 条）

**要什么**：组件树（Component Tree）、声明式 UI 布局系统（Layout Engine）、响应式数据绑定（Reactive State Management）。

**关键概念（务必能用自己的话说）**
- **Retained mode vs Immediate mode**：Qt/Flutter 是保留式（维护一棵长期存在的组件/Widget 树，状态变了做 diff 后重绘）；egui 是即时式（每帧重建 UI，简单但耗性能）。本岗位要做的是**保留式 + 声明式**，即「用声明式语法描述 UI，底层维护增量更新的树」。
- **组件树与 diff / reconciliation**：状态变化时如何最小化重建——这是性能的源头。
- **Layout Engine**：测量（measure）→ 布局（layout）两趟过程；父容器给约束（constraints），子节点返回尺寸；Flexbox 的主轴/交叉轴、Grid 的行列轨道。
- **响应式状态管理**：信号/订阅（signal-slot、observable），「数据变了谁需要重绘」的依赖追踪。

**怎么和你现有经历接上（面试话术）**
> 「我在海讯做 QT 可视化时，本质上就是在维护一棵 Widget 树 + 用信号槽做数据绑定；只不过那是保留式的手写命令式写法。我理解你们要做的是把这套东西**声明式化 + 增量更新**，核心难点在 diff 粒度和布局的测量/布局两趟开销，这正好是我做性能优化时最熟的那类问题。」

**今晚要补**：把上面 4 个加粗概念各写 3 句话；心里准备一个「如果让你设计一个组件树的 diff 算法，你会怎么做」的思路（key 比对 + 只重建脏节点 + 批量提交）。

### 1.2 渲染管线与图形性能优化（职责第 2 条）★最核心

**要什么**
- 设计并优化 **2D 图形渲染管线**，基于 **wgpu / Vello / Skia / Femtovg**
- 接入**硬件加速**，优化**局部重绘（Damage Region）**、**图层缓存**、**字体排版渲染（Text Shaping & Layout）**

**关键概念（必须能讲）**
- **CPU 光栅化 vs GPU 光栅化**：Skia/Femtovg 走 CPU 或 GPU 后端；wgpu 是纯 GPU 抽象层（对应 Vulkan/Metal/DX12，WebGPU 的 Rust 实现）。
- **wgpu 是什么**：Rust 的跨平台 GPU 图形 API 抽象，向下映射 Vulkan / Metal / D3D12 / OpenGL，向上被 Vello、egui、Iced 等使用。**这是本岗位最可能被直接问的库名**。
- **Vello**：基于 wgpu 的 GPU 2D 矢量渲染器（compute shader 做路径填充）。**Slint** 也是用 Vello/Femtovg 做渲染后端。
- **Skia**：Google 的 2D 库（Chrome/Flutter/Android 都用），最成熟但 C++ 体量大。**Femtovg**：轻量 OpenGL/Vulkan 的 2D 矢量渲染器（Slint 的默认后端之一）。
- **Damage Region / 局部重绘**：只重绘屏幕上真正变化的矩形区域（脏区合并），而不是整帧重画。嵌入式设备上这是省电省带宽的关键。
- **图层缓存（Layer Cache）**：把不常变的内容（背景、静态装饰）预烘焙成纹理层，动画时只合成（composite）图层，避免重复光栅化。
- **Text Shaping vs Text Layout**：
  - **Shaping（整形）** = 把字符序列变成**带位置的字形序列**（glyph + position），处理连字、双向文本、Kerning。**HarfBuzz** 就是干这个的（Qt/Chrome/Android 都用）。
  - **Layout（排版）** = 把字形排成行/段（换行、对齐、行高、断行规则）。
  - **FreeType** = 字体文件解析 + 字形光栅化（把 outline 变成位图）。
  - **cosmic-text** = Rust 生态里一站式文本排版库（内部用 rustybuzz/fontdb/swash）。
  - **字形缓存（Glyph Atlas）** = 把光栅化后的字形缓存进一张纹理图集，避免重复栅格化。
- **渲染管线大致流程**：布局 → 生成绘制指令（display list）→ 分层/damage 裁剪 → 提交 GPU（顶点/纹理/着色器）→ 合成上屏。

**怎么和你现有经历接上（面试话术——这段一定要背熟）**
> 「我做过两类和渲染/图形性能直接相关的事。
> 第一，在海讯用 QT 做**轨迹坐标解算与实时渲染界面**，涉及北天东 / 经纬高 / 地心三种坐标系互转，以及插值、旋转、数据复制，界面要跟着数据实时刷。
> 第二，我重构过**底层二进制数据框架**：原来是传统结构体按协议硬解，我改成基于 QByteArray 的**二进制流处理架构**，自动生成协议元数据 Record（字段偏移、字节长度、类型），同协议共享元数据，并封装了二进制 ↔ JSON 互转的通用接口。这本质上就是在设计一条**数据从原始字节到结构化对象的管线**，和渲染管线里『原始数据 → 绘制指令 → 上屏』的分层思路是同一类问题。
> 另外我做过一次比较硬的性能优化：协议转换引擎从串行版 500 万条数据 1 小时，通过中间表预抽取 + 分表分段多线程并行，压到 10 分钟以内。所以对**『先把管线拆阶段、再找瓶颈、再并行化』**这套方法论我是有实战的。」

**诚实边界（要主动说，别等被戳穿）**
> 「但我要说明清楚：我没有直接写过 wgpu/Skia 层面的代码，也没有做过 glyph atlas 或 damage region 的实现。我对这些的理解目前是**概念 + 原理层面**，动手是从 QT 的 QPainter/QWidget 那一层。不过我 C++ 内存/对象生命周期和 STL 是扎实的，QT 的渲染模型也熟悉，转到 wgpu/Vello 这层我认为是**学习曲线问题，不是能力问题**。」

**今晚要补（按投入产出排序，各 10 分钟足够）**
1. 各用一句话说清：wgpu、Vello、Skia、Femtovg、HarfBuzz、FreeType、cosmic-text。
2. Damage Region + 图层缓存 各讲 2 句（嵌入式为什么要）。
3. 能回答「为什么用 GPU 而不是 CPU 光栅化」→ 并行度高、省 CPU、适合大面积/动画；代价是传输带宽、小图元不划算。

### 1.3 跨平台与多后端适配（职责第 3 条）

**要什么**：桌面端 **Linux/Wayland/X11、Windows、macOS** + **嵌入式 DRM/KMS** 窗口管理、渲染后端对接、稳定交付。

**关键概念**
- **窗口系统分层**：应用 → 窗口抽象（**winit**）→ 平台后端（Wayland / X11 / Win32 / Cocoa / DRM-KMS）。
- **Wayland vs X11**：X11 是老的 C/S 架构（有 X Server，跨网络，历史包袱重）；Wayland 是合成器直管（客户端渲染到自己 buffer，交给 compositor 合成），更安全更省拷贝，但生态兼容性仍在过渡。
- **Why 嵌入式用 DRM/KMS**：Direct Rendering Manager / Kernel Mode Setting 是 Linux 内核直接管显示控制器和 framebuffer 的子系统；嵌入式设备资源有限，不跑 X11/Wayland 那一整套，直接走 DRM 出图更省、启动更快、更可控。
- **Event Loop（事件循环）**：窗口系统事件（输入、重绘、定时器）的派发循环；GUI 框架的心跳。要能说：事件队列 → 派发给对应组件 → 触发状态更新 → 标记脏区 → 下一帧重绘。
- **IME / 输入法、HiDPI 缩放、多显示器 DPI** 是跨平台最常翻车的地方（能提一句就是加分）。

**话术**：「我没有直接做过 winit/Wayland 的适配，但我 Linux 下开发、docker/compose 部署是日常，QT 也是跨平台框架，对『抽象层 + 平台后端』这一套分层设计不陌生。」

### 1.4 语言绑定与 DSL / 过程宏研发（职责第 4 条）

**要什么**：声明式 UI 标记语言的**解析器/编译器**（DSL），以及 Rust **过程宏（proc-macro）**，目标是「开箱即用的极致 DX」。

**关键概念**
- **proc-macro 三类**：`#[derive(...)]`（派生宏）、属性宏（attribute，如 `#[component]`）、函数式宏（function-like，如 `view!`）。运行在**编译期**，输入输出都是 `TokenStream`。
- **DSL 编译流程**：源码文本 → 词法（tokenize）→ 语法（AST）→ 语义/类型检查 → 生成 Rust 代码（代码生成）→ 编译器继续编译。
- 典型参考：Slint 的 `.slint` 语言、egui 的 `ui.label()`、Leptos/Dioxus 的 `view!` 宏、Yew 的 `html!` 宏。

**话术**：「proc-macro 我没写过。但我写过**协议元数据自动生成**的东西——根据协议定义自动生成字段偏移/长度/类型的元数据表，思路和代码生成是通的。另外我写过二进制协议转换引擎、做过 Java 微服务项目，对『描述 → 解析 → 生成』这条链路有手感。」

### 1.5 跨语言互操作 FFI（职责第 5 条）

**要什么**：Rust 与 **C/C++/Qt** 存量库的 FFI 安全封装 + 高性能通信，支撑**渐进式重构**。

**关键概念**
- Rust 侧工具：`#[no_mangle] extern "C"`、`bindgen`（C 头文件 → Rust FFI 声明）、`cxx`（Rust ↔ C++ 安全桥）、`cbindgen`（Rust → C 头文件）。
- 几个必答点：**ABI 稳定性**（只有 `extern "C"` 稳定）、**`unsafe` 边界必须最小化并用安全 API 包住**、**所有权跨越 FFI 时谁负责释放**、**panic 不能穿越 FFI 边界**（要 catch 或 abort）、字符串/内存布局差异（`String` vs `char*`）。
- 「渐进式重构」= 老 C++/Qt 代码不动或只开洞，新功能用 Rust 写，两边通过 FFI 通信，逐步替换。这是**最现实的落地路径**，面试讲这个会显得很懂工程。

**话术**：「这块我能讲思路：先把 unsafe 收缩到最薄的一层封装，对外暴露安全 API，明确内存所有权归属，避免 panic 跨边界。我做过 C++ 与 Java 服务联调、封过统一的二进制数据处理接口，对跨语言边界的设计不陌生。」

### 3.6 如果问技术细节（Rust 概念题）

**诚实分层回答法**——这个模板可以套用所有你半懂的问题：
> 「这个概念我**自己的理解**是 XXX（讲你确实懂的）。不过我没有在 Rust 里实际踩过这个坑，**如果理解得不对请您指正**。」

**必须能开口的 5 个概念（今晚各花 10 分钟）**
1. **所有权**：每个值有唯一 owner，owner 离开作用域即释放；move 语义默认。
2. **借用与生命周期**：`&T` 可多个共享 / `&mut T` 独占；生命周期标注是**给编译器证明引用不会悬垂**，不是延长生命周期。经典报错 `borrowed value does not live long enough`、`cannot borrow as mutable because it is also borrowed as immutable`。
3. **Unsafe**：不是「关掉检查」，而是「**由你承担编译器无法验证的保证**」；FFI、裸指针、`transmute`、实现 `Send/Sync` 时才需要；原则是**把 unsafe 收缩到最薄一层，对外暴露安全 API**。
4. **Send / Sync**：`Send` 能跨线程转移所有权；`Sync` 能被多线程共享引用；`Rc` 不是、`Arc` 是。并发里 `Arc<Mutex<T>>` 是常见组合。
5. **Trait / 泛型**：trait 类似接口但可做**静态分发（泛型单态化）**或**动态分发（`dyn Trait`）**；`impl Trait` 与 `dyn Trait` 的区别。

**如果被问到完全不会的**：
> 「这块我还真没接触过，回去我查一下。**我能说一下我的猜测吗？**……」
——**不要沉默，也不要瞎编**。展示思考过程比答对更重要。

**⚠️ 三个注意**
1. **一定要问清楚薪资结构**：几薪？有没有绩效/项目奖金？试用期打折多少（常见 80%）？五险一金基数？
2. **异地成本要算进去**：上海的房租和生活成本 vs 西安。**17K 在上海的体感大概相当于西安的 11–12K**。如果对方压到 17K，要慎重。
3. **不要报一个自己都不接受的数字**，也不要为了拿到 offer 先报低价——**低报之后再涨很难**。

### 3.8 其他常规题（快速过）

| 问题 | 要点 |
| --- | --- |
| 「为什么选我们而不是大厂？」 | 说**方向匹配**（GUI 框架从 0 到 1）+ **团队背景**，不要说「大厂进不去」 |
| 「职业规划？」 | 3 年目标：成为**图形/GUI 框架方向**能独立负责模块的工程师；1 年目标：把 Rust 和渲染管线吃透 |
| 「什么时候能到岗？」 | 给**确定日期**（建议「一周内可以到上海，两周内入职」这种明确答复） |
| 「能接受加班吗？」 | 「项目冲刺期能接受，我上家做协议引擎优化那阵也加过班。我更在意的是**效率**，我自己会做性能优化这块。」（别说「从不加班」，也别说「随便加」） |
| 「平时怎么学习的？」 | 说具体的：看源码（wgpu/Slint）、写练习、做开源项目、读论文（你有 TKDE/电子学报的论文，可提） |
| 「你最大的缺点？」 | 选一个**真实但不致命**的 + 改进动作。例：「在纯业务逻辑的代码上我耐心一般，所以我会刻意用测试和接口设计来约束自己」 |
| 「还有别的问题吗？」 | **必须问**，见下 |

### 3.9 反问清单（**这个必须准备！**）✨

按优先级排，电话里挑 2–3 个问，面试时再补：

**关于岗位与团队（优先）**
1. 「这个岗位目前最急的是哪一块？是渲染管线、布局引擎，还是跨平台适配？」
2. 「团队现在多少人？Rust 这块是全新写的，还是有从 C++/Qt 迁移的存量代码？」
3. 「我入职后会负责哪个模块？直接汇报给谁？」

**关于技术（展示你的兴趣）**
4. 「渲染层现在是在 wgpu / Vello / Skia 里做选型，还是已经定了？」
5. 「嵌入式 DRM/KMS 那条线是面向工业/军工客户的交付项目，还是框架自身要支持的平台？」

**关于流程与待遇（电话末段问）**
6. 「接下来的流程大概是怎样的？有几轮？会有笔试或者编码测试吗？」
7. 「薪资结构是怎样的？几薪、试用期比例、五险一金基数？」

> ⚠️ **不要在第一次电话就密集问待遇**，问 1 个流程类问题就够，待遇留到 HR 主动提或下一轮。

## 4. 明天电话前 · 30 分钟准备清单

- [ ] **想清楚第 1 个问题**：人在哪、能不能来上海、什么时候能到岗。**准备好一句确定的话。**
- [ ] **统一两段空窗的说法**，写下来念两遍，确保和简历一致、不重叠、不矛盾。
- [ ] **背熟 §1.2 的渲染话术**（QT 可视化 + QByteArray 重构 + 6 倍性能优化）——这是你唯一的「主场」，一定要流畅。
- [ ] **背熟 §3.4 公司理解**（三段式：定位 / 技术理解 / 个人动因）。
- [ ] **想好 Rust 那题的完整回答**（承认 → 迁移 → 主动提试做 Demo）。
- [ ] **薪资区间定下来**（建议 20–25K），并想好「为什么值这个数」的理由。
- [ ] **准备 2 个反问**（岗位最急的模块 + 团队构成）。
- [ ] **一个具体的 Rust 学习证据**（写了什么、卡在哪、怎么解决的）——哪怕很小，**必须具体**。
- [ ] 环境：找个**安静、信号好**的地方；简历和这份文档放在手边；**别在嘈杂环境接电话**。
- [ ] 心态：这是一次**双向了解**，不是考试。你手上的「QT 图形 + 底层重构 + 性能优化」组合，在这个岗位的候选人池里**是有竞争力的**。

**电话结束前一定要说的两句**
1. 「方便的话，后续流程和时间点能麻烦您同步一下吗？」
2. 「如果贵司有需要，我可以做一个小的 Demo 或者参与试做任务，这样您们判断会更直接。」
